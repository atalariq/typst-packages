### Oracle 21c Quirks

**No `DROP ... IF EXISTS`** (ditambahkan di 23c). Gunakan anonymous PL/SQL blocks:

```sql
BEGIN
    EXECUTE IMMEDIATE 'DROP TABLE table_name CASCADE CONSTRAINTS PURGE';
EXCEPTION
    WHEN OTHERS THEN NULL;
END;
/
```

Catatan lain:
- `GENERATED BY DEFAULT AS IDENTITY` didukung (sejak 12c)
- `CREATE OR REPLACE TRIGGER` works fine
- `!=` works as not-equal (tapi `<>` lebih portable)
- No `SERIAL` pseudo-type (gunakan identity columns)

## Struktur Laporan

### Format Standar (lengkap)
1. Cover (`use-cover: true`)
2. Tujuan Praktikum
3. Dasar Teori (1 paragraf per konsep/subsection)
4. Hasil dan Pembahasan (Tugas Praktikum + Latihan)
5. Kesimpulan
6. Daftar Pustaka

### Format Minimal (sering diminta user mepet waktu)
1. Cover
2. Hasil dan Pembahasan saja

> **Pola "minimal report":** Ketika user bilang "cuma cover sama hasil dan pembahasan" atau "gak usah tujuan/dasar teori/kesimpulan", generate report dengan hanya Cover + `= Hasil dan Pembahasan`. Tidak perlu Tujuan, Dasar Teori, atau Kesimpulan. Tetap sertakan `#daftar-isi()` di awal.

## Konvensi SQL & Trigger
- Gunakan `CREATE OR REPLACE` untuk _trigger_ dan _view_ agar idempoten.
- Gunakan anonymous block dengan `EXECUTE IMMEDIATE` dan `WHEN OTHERS THEN NULL` untuk _drop_ tabel/trigger yang mungkin belum ada — Oracle 21c tidak mendukung `DROP ... IF EXISTS`.
- `FOR EACH ROW` wajib untuk trigger yang mengakses `:OLD` / `:NEW`.
- `BEFORE` untuk modifikasi/validasi sebelum commit; `AFTER` untuk audit/logging.
- `BEFORE UPDATE OF column_name` lebih efisien daripada trigger tanpa `OF`.

## Recurring PL/SQL Patterns

### 1. Trigger for Backup on DELETE
```sql
CREATE TABLE backup_table AS SELECT * FROM original_table WHERE 1 = 0;

CREATE OR REPLACE TRIGGER trg_table_backup_delete
BEFORE DELETE ON original_table
FOR EACH ROW
BEGIN
    INSERT INTO backup_table (...) VALUES (:OLD.col1, :OLD.col2, ..., SYSDATE, USER);
END;
/
```

### 2. Trigger for Change Tracking
```sql
CREATE TABLE change_log (
    id       NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    ref_id   NUMBER NOT NULL,
    changed  DATE NOT NULL,
    old_val  NUMBER,
    new_val  NUMBER
);

CREATE OR REPLACE TRIGGER trg_table_price_log
BEFORE UPDATE OF tracked_column ON original_table
FOR EACH ROW
BEGIN
    IF :OLD.tracked_column != :NEW.tracked_column THEN
        INSERT INTO change_log (...) VALUES (:OLD.id, SYSDATE, :OLD.val, :NEW.val);
    END IF;
END;
/
```

### 3. View with READ ONLY
```sql
CREATE OR REPLACE VIEW v_name AS
SELECT ... FROM ... WHERE ...
WITH READ ONLY;
```

### 4. Audit Columns Pattern
```sql
deleted_at DATE NOT NULL,   -- SYSDATE
deleted_by VARCHAR2(128)    -- USER (Oracle session user)
```

### Testing & Verification
Selalu sediakan test queries yang bisa dijalankan step by step:
- `SELECT` before untuk melihat data
- `DELETE`/`UPDATE` untuk memicu trigger
- `SELECT` dari audit table untuk verifikasi
- `ROLLBACK` untuk undo test

### Debugging Queries
```sql
-- List all triggers in schema
SELECT trigger_name, table_name, status, trigger_type, triggering_event
FROM user_triggers
ORDER BY trigger_name;

-- View trigger body
SELECT trigger_body FROM user_triggers WHERE trigger_name = 'TRG_NAME';

-- Enable/disable
ALTER TRIGGER trg_name DISABLE;
ALTER TRIGGER trg_name ENABLE;
```

## Aturan Konten & Style

### SQL Code Blocks
- Gunakan `#code(numbering: false, ```sql ... ```)` untuk snippet SQL.
- Gunakan `#include-code()` hanya jika source file `.sql` tersedia dan user sudah mengkonfirmasi.
- SQL dijelaskan dalam bahasa Indonesia formal, pasif, tanpa first/second person pronoun.

### Screenshot
- **Wajib** untuk setiap operasi DDL (`CREATE`, `ALTER`, `DROP`) dan DML (`INSERT`, `UPDATE`, `DELETE`) — termasuk hasil _query_ dan pesan konfirmasi/error.
- Screenshot diberi nama file deskriptif: `tugas-{nomor}.{sub}.{deskripsi}.png`
  - Contoh: `tugas-1.1-create_table.png`, `tugas-2.3-verify_price_change.png`
- Gunakan `#rect[TODO: ...]` sebagai placeholder screenshot yang belum diambil.
- Caption gambar harus **single-line, padat** — tidak multi-line.

### Penjelasan
- Jelaskan mekanisme SQL/trigger: _pseudorecord_ (`:OLD`, `:NEW`), tingkat eksekusi (`FOR EACH ROW` vs statement), timing (`BEFORE` vs `AFTER`).
- Jelaskan kenapa suatu pendekatan dipilih (misal: kenapa `BEFORE DELETE` bukan `AFTER DELETE`).
- Setiap error Oracle yang muncul harus dijelaskan kode error dan penyebabnya.

## Page Break & Layout
- `#pagebreak()` sebelum `= Hasil dan Pembahasan`
- `#pagebreak()` antara setiap `== Tugas`
- `#pagebreak()` sebelum `= Kesimpulan` (jika ada)
- `#col(...)` hanya untuk snippet pendek (< 15 baris per sisi). Untuk source SQL panjang, gunakan full-width `#code()` diikuti `#img()` di bawahnya.

## Lampiran
- Gunakan `#heading(level: 1, numbering: none)[Lampiran]` tanpa `outlined: false` agar muncul di Daftar Isi.
- Lampiran berisi source code `.sql` lengkap via `#include-code()`.
